AI Mentor

Recording cheat sheet. Demo 1 is filmed for real - two live AI windows side by side. Demo 2 is the Ruleset Master Trove opt-in.

Standing recording rules - do these before you hit record

  1. Hide the macOS Dock. System Settings > Desktop & Dock > Automatically hide and show the Dock: ON.
  2. Hide the app sidebar. ChatGPT, Claude and Gemini all collapse theirs - collapse it before the first frame, not mid-take.
  3. Hide the browser bookmarks bar. Cmd+Shift+B.
  4. Hide the URL / address bar wherever possible. Full screen, or a distraction-free window. Where the URL has to be visible because it is the point, show only that one URL and nothing around it.

Why: the frame should show the work, not the machine. Every one of these is a leak path - open tabs, bookmarks, internal URLs, folder names and staff names have all reached a customer-facing frame before. Hiding them costs four seconds and removes the whole class of problem.

Demo 1 - "Same file, two answers" (filmed, not clicked)

What it is: two real AI windows answering the same question about the same file, and disagreeing. Pre-record it and cut it. Two live windows racing on camera is exactly the unpredictable case the standard says to pre-record - if a take drifts, retake it and cut, do not try to rescue it live.

The whole demo is two interactions: drag the file in, ask the question. Then one follow-up exchange for the second beat. Nothing else.

Before you hit record - what is open, and in what state

  1. Two windows of the same size, side by side, filling the screen. Same theme, same zoom level, same font size, same model selector state. The viewer has to believe nothing differs but the rules.
  2. Left window: stock AI. Nothing loaded. A genuinely fresh conversation.
  3. Right window: the ruleset already loaded, off camera, before the first frame. Loading it is not part of this demo and must not be in shot.
  4. Both windows visibly empty at the first frame. No prior turns, no scrollback, no sidebar chat history, no window or tab title that reveals which one is which.
  5. Web search switched on in the right-hand window. Without it the outside-proof beat cannot happen, and that beat is the whole demo. Confirm it actually fires before the take, in a throwaway window you then close.
  6. The operating-data file renamed and sitting ready to drag - one neutral filename, one visible folder or the desktop, nothing else in that folder. The filename is on screen during the drag.
  7. One file, not two. The same file object goes into both windows. If you prepared two copies, delete one now.
  8. The four standing rules above applied to both windows - Dock, sidebars, bookmarks bar, URL bar.

The sequence on camera

  1. Establish the pair. Hold on both windows, empty and identical. Stock AI left, ruleset AI right. Do not narrate over this - let it be seen.
  2. Drag the same file into the left, then into the right. One continuous shot if you can. "Same file" is the claim the demo rests on, so it has to be visibly the same file, in the same moment.
  3. Type the same question into both, word for word:
I've spent a year turning this around and cut every cost. Can I save it?
  1. Left answers yes. Encouraging, well-reasoned, citing the improving loss. Let it run in full. The left answer being reasonable is what makes the right answer land - do not cut it short to save time.
  2. Right answers no - this isn't a cost problem - and then leaves the document to go and find proof the file never contained. This is the wow. Hold on the moment it goes outside. Both had the same file; only one went looking for what the file did not say.
  3. Second exchange, same pair, same file: what do we do about it. Left says shut it down. Right says don't shut it down - sell the assets. Hold on the $440,000. That is the closing image of Demo 1.

What must not be on screen

  • The ruleset being loaded into the right-hand window. That happens before the take.
  • Any window title, tab, URL or bookmark naming a demo page or an internal repo.
  • Sidebar chat history in either window.
  • Any second copy of the data file, or a folder with other files in it.
  • Any hesitation take where the two windows got different prompts. Re-shoot it.

On screen: blur, show, never say

BlurShow sharp - deliberately
The business unit's real name, the parent revenue line, every client, customer and supplier name, the buyer's identity, the test email used for the download, any real personal name typed into the form, the bookmarks bar, other tabs, and the sidebar chat history in the fresh chat. The profit trend, the cost-per-customer line, the outside-proof chart, both outcome figures, all four form fields including the blunt one, the ten-message rule, and the full pushback exchange.

Rename the data file before you drag it. The filename is on screen during the drag.

Never say - and never let it appear in the interface either: system prompt, config file, context window, temperature, token. Two of these are currently spoken in the script and need re-voicing.

Record-day dependency: web search must be switched on in the assistant, or the outside-proof beat cannot happen.

Demo 2 - the Ruleset Master Trove LIVE, VERIFIED 200

The opt-in page you film:

https://theaishift.biz/tools/ai-mentor/master-trove/

Page heading on the live form reads Ruleset Master Trove, section heading The Decision You Are Weighing. This one may be filmed live.

The six fields that actually exist - all required, film all of them

  1. Your Name
  2. Email Address
  3. What Decision Are You Trying to Make?
  4. What Are the Relevant Numbers?
  5. What Does Your Business Do?
  6. What Answer Are You Hoping to Hear?

Field 6 is the one that makes the tool make sense. Do not soften it, do not skip past it, and do not paraphrase the label. Answer it honestly on camera - the honesty is the demonstration.

After the file arrives

  1. Open the delivered file. It is one pasteable asset - five steps plus a three-part test section.
  2. Hold on the ten-message re-read rule - it sits in its own boxed callout and has to be readable when the shot zooms.
  3. Paste the file into a fresh chat, then type:
Here's the decision I'm facing. Tell me what you actually think, not what I want to hear.

OPEN QUESTIONS - answer before filming

  1. The operating-data file premise: which version is true on camera? Is it dressed to look like a business that is recovering, or is it the data you actually had at the time? You own this story, so you decide - but the answer changes the voiceover, and the file itself has not been built yet.
  2. The script carries its own unresolved flag on that same file. The asset brief as written instructs the builder to make the unit "look like it's recovering" and states that if the answer is findable inside the file there is no demo. The script records that this engineers the input so the stock AI is guaranteed to fail, while the narration presents the file as real operating data, and proposes instead building it as what was actually available at that point in the story. The demo package logged this as requiring confirmation from the person whose story it is. That confirmation was never obtained. It is still open, and the file cannot be built until it is settled.
  3. Which two AI tools are on screen, and are they the same product? Undecided. Either one product in two windows - one with the ruleset loaded, one without - or two different products. One window is stock and one has the rules, so the same-product version is the honest comparison and the easier one to keep visually identical; two different products would need the narration to say so. Decide before you set the windows up, because it changes what "identical and visibly empty" means at the first frame.
  4. Runtime. The current cut targets longer than the ceiling. What comes out?
  5. Two banned terms are in your spoken script. Approve the replacement wording before the read, not during it.
  6. The ten-message line. A rewording has been proposed that drops the "so it can't drift" clause. Yes or no?
  7. Has this video's Ruleset content been build-verified end to end? Nobody has confirmed a real lead receives what this demo promises.
